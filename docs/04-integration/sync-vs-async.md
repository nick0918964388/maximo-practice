# 整合模式：同步 (Sync) vs 非同步 (Async) 的場景選型

在設計 Maximo 的整合架構時，最常被問到的問題是：「我應該用 REST API 同步呼叫，還是要用訊息隊列（Kafka/MQ）做非同步對接？」這篇文章幫你做出正確的技術決定。

---

## 1. 同步整合 (Synchronous)

通常指客戶端直接發送 REST HTTP 請求，並「等待」Maximo 回傳結果。

### 🚀 適用場景
- **查詢類操作**：例如在手機 App 上即時查詢資產狀態。
- **高即時性驗證**：例如外部系統需要立刻知道這張工單是否成功建立，才能進行下一步。

### ⚠️ 缺點與風險
- **系統耦合度高**：如果 Maximo 正在維護或重啟，外部系統會直接報錯。
- **效能威脅**：如果同步請求量極大，會佔用大量 Manage Pod 的執行緒（Threads），甚至拖慢介面速度。

---

## 2. 非同步整合 (Asynchronous)

指客戶端將訊息丟給中介（如 Kafka、JMS Queue 或 Webhook），Maximo 後續再進行處理。

### 🚀 適用場景
- **大量資料同步**：例如從 ERP 批次同步 5 萬筆物料主檔。
- **容錯要求高**：即使 Maximo 暫時當機，訊息仍存在隊列中，恢復後會自動重補。

### ⚠️ 缺點與風險
- **開發複雜度**：需要處理「最終一致性」問題。
- **追蹤困難**：如果不建立完善的日誌機制，很難知道某一筆訊息到底卡在哪個環節。

---

## 3. 戰略選型建議表

| 需求特性 | 推薦模式 | 常用工具 |
| :--- | :--- | :--- |
| **查詢 (Query)** | **同步** | OSLC REST API |
| **少量/即時更新** | **同步** | OSLC REST API |
| **大量/批次資料** | **非同步** | Integration Framework (IFAC) |
| **外部系統觸發 (Event)** | **非同步** | Webhook / Kafka |
